# Two Modes Implementation Plan (Bifröst step 2a)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sleipnir runs either alone (one machine, the local token, no people) or as a Bifröst
extension (a private socket, identity from Bifröst's headers), and is called `sleipnir`.

**Architecture:** One engine and one API. The server gets a `Caller` (who is calling, and what they
may do) from one of two front doors: `LocalTokenDoor` (alone, loopback TCP) or `BifrostDoor` (under
Bifröst, a Unix socket). The users, devices and SQLite store built in step 3a are deleted: they live
in Bifröst now.

**Tech Stack:** .NET 10, ASP.NET Core minimal APIs on Kestrel (TCP and Unix sockets), xUnit.

**Spec:** `Sleipnir/docs/superpowers/specs/2026-11-13-sleipnir-service-design.md` (§4.2, §6, §7, §8.1,
§9) and `Bifrost/docs/design.md` (§8.4, §8.5, §8.8).

## Global Constraints

- The command is `sleipnir`, the data folder `sleipnir`, the user unit `sleipnir.service`. No
  transition from `dnm` (owner, 2026-11-14): old folders are left untouched and not read.
- Partial files keep the `.dnm` extension (spec §7.3 names it).
- Alone: loopback only, port 7766, `Host` allowlist, local token in the `Authorization` header.
- Under Bifröst: no TCP port at all. The socket path, data folder and extension name come from the
  environment Bifröst sets (below). Sleipnir refuses to start in that mode if any is missing.
- Never both front doors at once (spec §6.3).
- Errors are problem+json with a stable `code`.

**The extension contract** (also used by Bifröst plan 2b; values fixed here):

| Item | Value |
|---|---|
| Command | `<program> extension` |
| `BIFROST_SOCKET` | Path where the extension listens (Unix socket, created by the extension, mode `0600`) |
| `BIFROST_API_SOCKET` | Path of Bifröst's API socket for this extension (used from plan 2d) |
| `BIFROST_DATA_DIR` | The extension's own data folder |
| `BIFROST_EXTENSION` | The extension's name (`sleipnir`) |
| `BIFROST_INTERFACE` | `1` |
| Identity headers | `X-Bifrost-Person-Id` (GUID), `X-Bifrost-Role` (`admin`/`member`), `X-Bifrost-Device-Id` (GUID), `X-Bifrost-Device-Kind` (`app`/`browser-fallback`) |
| Path | Bifröst strips `/x/<name>`; the extension sees `/api/v1/…` |

## Review Focus

1. **Identity headers missing, duplicated, or malformed** (two `X-Bifrost-Role` values, `Admin`
   with a capital, a non-GUID id): `401 no_identity`, never a default of admin. Test in Task 3.
2. **A `browser-fallback` device trying to change anything**: `403 view_only` on every POST and
   DELETE, while it can still list its own downloads. Test in Task 3.
3. **A member's download that redirects to `http://127.0.0.1/` or resolves to `192.168.1.1`**: the
   download fails with `destination_not_public`, and an admin's identical download works. Test in Task 4.
4. **A stale socket file left by a crashed extension**: the next start replaces it and listens.
   Test in Task 3.
5. **Under Bifröst, a client sends `destination`**: `400 destination_not_allowed`; the file lands in
   the person's interim folder. Test in Task 3.

**Interfaces:**

- Produces:
  - `record ExtensionEnvironment(string Socket, string? ApiSocket, string DataDir, string Name)` with
    `static ExtensionEnvironment? Read(Func<string, string?> env, out string? missing)` — null and the
    missing variable's name when `BIFROST_SOCKET`, `BIFROST_DATA_DIR` or `BIFROST_EXTENSION` is unset,

    occur exactly once; ids parse as GUIDs; role is exactly `admin` or `member`; kind exactly `app` or
    `browser-fallback`. `Caller(personId, role == admin, kind == browser-fallback)`.
  - `sleipnir extension`: exit 64 with `"sleipnir extension is started by Bifröst: <VAR> is not set."`
    when `Read` fails; otherwise the engine with its JSON state in `<DataDir>/state`, instance lock in
    `<DataDir>`, downloads into the interim folder `<DataDir>/downloads/<person-id>/` [my call: until
    Bifröst's folders, step 6]; stops cleanly on SIGTERM.

- Test: `tests/Sleipnir.Tests/PublicAddressTests.cs`, `HttpNetworkClientTests.cs`, `ExtensionDoorTests.cs`

**Interfaces:**
- Produces: `static class PublicAddress { static bool IsPublic(IPAddress address); }` — false for
  loopback, unspecified, RFC 1918, 100.64.0.0/10 (CGNAT), 169.254.0.0/16, multicast, broadcast,
  0.0.0.0/8, IPv6 `::1`, `fc00::/7`, `fe80::/10`, `ff00::/8`, and IPv4-mapped forms of all of these.
  Error code on the task: `destination_not_public`.

The check runs in the existing `ConnectCallback`, on the address actually dialled, so it covers
redirects and DNS rebinding (spec §9). The request says whether it applies through an
`HttpRequestOptionsKey<bool>`, set from the task's flag. A member's download sets the flag; an
admin's does not (spec §7.5).
